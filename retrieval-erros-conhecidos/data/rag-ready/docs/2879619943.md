### 1.1 Falha na etapa Deployment config com o erro: WASX7070E: The configuration service is not available

🧠 Resposta da BIA TECH – A etapa de deploy falhou.

Olá! 👋

Identificamos falha ao checar se a aplicação existe no Websphere.

🔍 O que isso significa?
A etapa de deploy irá falhar ao atualizar a aplicação no ambiente.

🛠️ Etapa de falha
Deployment config

✅ O que você deve fazer:

- Acionar o time do WebSphere e informar o log de erro, nome do repositório e canal.
- Caminho para abertura da RITM no Service Now:Início → Portal Aiops → Ambiente Open → Websphere → Suporte Correção de Problema
- Após a correção do lado do ambiente (reciclagem do cluster), realizar um rerun no job com falha.
🎯 Motivo:
Erro Deploy

👥 Time responsável:
Infraestrutura

### 1.4 Lost connection - erro SSH (Permission denied / Too many authentication failures)

🧠 Resposta da BIA TECH – Falha de permissão no acesso SSH ao servidor remoto

Olá! 👋

Erros de acesso via SSH a servidores remotos podem estar relacionados à falta de permissão do usuário e ocorrem na etapa de Deployment on Server.

🔍 O que isso significa?
A etapa de deploy irá falhar apresentando a mensagem "Permission denied".

🛠️ Etapa de falha
Deployment on Server

✅ O que você deve fazer:

- Verificar a falha de SSH nos logs.
- Confirmar se a mensagem contém "Permission denied".
- Acionar:rafael.o.rocha@bradesco.com.br (mailto:rafael.o.rocha@bradesco.com.br)
- ou carlos.portella@bradesco.com.br (mailto:carlos.portella@bradesco.com.br)

- Solicitar o permissionamento necessário.
- Após ajuste, executar rerun da etapa com falha.
🎯 Motivo:
Erro Deploy

👥 Time responsável:
Infraestrutura

### 1.5 Erro de permission denied no WebSphere (fileTableLock)

🧠 Resposta da BIA TECH – Erro de permissão de escrita no WebSphere

Ocorreu um erro de permission denied ao tentar realizar o deploy no WebSphere.

🔍 O que isso significa?
Falta de permissão de escrita nos diretórios internos do WebSphere, impedindo que o processo finalize.

### 1.6 Erro No such file or directory no WebSphere

🧠 Resposta da BIA TECH – Problema de owner (usuário root vs wasusr)

Olá! 👋

🔍 O que isso significa?
Os serviços foram iniciados com usuário root, enquanto deveriam utilizar wasusr, causando restrição de acesso.

✅ O que você deve fazer:

- Validar owner das pastas em:/suportedbdc/WebSphere*
- Abrir incidente solicitando:Ajuste de owner para wasusr
