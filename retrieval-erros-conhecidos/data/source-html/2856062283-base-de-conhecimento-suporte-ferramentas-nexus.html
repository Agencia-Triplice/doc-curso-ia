1. Nexus


1.1 Erro 400 na esteira ao publicar a imagem no Nexus na etapa de build - ERROR: status: 400 Repository does not allow updating assets

🧠 Resposta da BIA TECH – A versão do artefato publicado no Nexus já foi publicada

Olá! 👋
Identificamos que o erro 400 ocorreu devido ao fato de que a versão do artefato publicado no Nexus já existe. O processo de CI realiza uma requisição para o Nexus na tentativa de publicar o artefato gerado pela esteira na etapa de build e então nesse caso falha porque a própria ferramenta não permitir publicar versões de artefatos que já foram publicadas em builds anteriores, lançando a seguinte mensagem: 400 Repository does not allow updating assets

🛠️ Etapa de falha

 Execute fortify/Publicar aplicação NodeJS/Angular (Registry)/Upload config and swagger to nexus/Upload Package to Nexus

🔍 O que isso significa?

A esteira checa se a versão adicionada no pom.xml ou package.json já existe no Nexus e caso exista o erro 400 é gerado.

✅ O que você deve fazer:

  1. Acesso o diretório principal do projeto.
  2. Verificar o arquivo de configuração de build. Dependendo da tecnologia pode ser pom.xml, package.json, ou no main.py.
  3. Localizar a tag de version e incrementar a versão da aplicação.
  4. Efetuar um novo build.

Por exemplo, no caso do pom.xml a versão da aplicação é representada pela <version>

    <groupId>br.com.bradesco.cardtech.cloud</groupId>
    <artifactId>svmp-srv-visa-notifica-consumidor</artifactId>
    <version>0.0.2</version>

No caso deveria ser ser incrementada para 0.0.3.

🎯 Motivo:
Erro Build

1.2 Erro com Buld/Push Docker Image - ERROR: failed to build: blob upload invalid: blob upload invalid

🧠 Resposta da BIA TECH – Ao efetuar o re-run a esteira tentou publicar uma tag de versionamento da imagem já existente no Nexus.

Olá! 👋
Identificamos que a etapa Build/Push Docker Image falhou porque ao efetuar o re-run a esteira tentou publicar uma tag de versionamento da imagem já existente no Nexus.

🔍 O que isso significa?

A esteira checa se a versão adicionada no pom.xml ou package.json já existe no Nexus e caso exista o erro 400 é gerado.

✅ O que você deve fazer:

  1. Realizar um novo build e deploy para que uma nova tag da imagem seja gerada e publicada corretamente no Nexus.

🎯 Motivo:

Erro Build

👥 Time responsável:

Desenvolvimento


2. ArgoCD

2.1 Erro Unable to load data: permission denied - Falha ao acessar o ArgoCD

🧠 Resposta da BIA TECH – Falha temporária no carregamento das informações de apps disponíveis

Olá! 👋
Identiticamos que ao tentar acessar as suas apps no ArgoCD, ocorreu um timeout pra carregar as informações dos seus grupos.

🔍 O que isso significa?

A quantidade de apps disponíveis do seu grupo não pode ser carregada no tempo estabelecido

✅ O que você deve fazer:

  1. Favor aguardar 5 minutos
  2. Logar novamente no ArgoCD usando uma aba anônima
  3. Se possível, acesar a app desejada através do link direto informado na log do build

🎯 Motivo:

Erro de timeout

👥 Time responsável:

Desenvolvimento
