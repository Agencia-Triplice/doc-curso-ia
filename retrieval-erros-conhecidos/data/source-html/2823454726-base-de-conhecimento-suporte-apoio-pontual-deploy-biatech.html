1.1 🚀 Como fazer o Build da aplicação após a migração da TI-Híbrida para o GitHub (Deploy On-Premise x GitHub)

🧠 Resposta da BIA TECH – A etapa de build da aplicação após migração para o GitHub requer ajustes importantes.

Olá! 👋

🔍 O que isso significa?
Após a migração da TI-Híbrida para o GitHub, sua aplicação pode exigir adequações em segurança, dependências e workflows para que o build funcione corretamente no novo modelo.

✅ O que você deve fazer:

  1. Validar ferramentas de Segurança 🔐 e Qualidade ✔️ após a migração.
  2. Verificar se a imagem base utilizada está homologada e sem vulnerabilidades.
  3. Ajustar dependências internas — solicitar vínculo Nexus entre repositórios antigo e novo (uso de VS_KEY).
  4. Configurar workflows para builds em outras branches além da main.
  5. Utilizar o workflow migrate-workflow-branch.yaml para replicar workflows.
  6. Executar o build após ajustes e validar resultado.
  7. Em caso de falha, abrir chamado via BEX Access.

1.2 📦 Como fazer o Deploy da aplicação após a migração da TI-Híbrida para o GitHub (Deploy On-Premise x GitHub)

🧠 Resposta da BIA TECH – A etapa de deploy no GitHub segue nova estrutura baseada em repositórios separados.

Olá! 👋

🔍 O que isso significa?
Após a migração, o deploy passa a utilizar repositórios distintos para aplicação e configuração, mantendo a estrutura de ambientes do OCP.

✅ O que você deve fazer:

  1. Identificar os dois repositórios:
    • nome-da-aplicação → código
    • nome-da-aplicação-config → infraestrutura
  2. Utilizar as branches por ambiente no repositório config:
    • TU → 🧪 Sandbox
    • TI → 🔍 Testing
    • TH → 🏗️ Staging
    • PR → 🚀 Produção
  3. Executar o workflow values-ocp-config.yaml para importar configurações existentes.
  4. Validar os values e configurações geradas.
  5. Realizar o deploy conforme ambiente desejado.

1.3 📦 Erro de certificado ao tentar publicar artefatos (lerna) no Nexus

🧠 Resposta da BIA TECH – Falha na publicação de artefatos no Nexus durante pipeline.

Olá! 👋

🔍 O que isso significa?
O artefato não está sendo publicado corretamente no Nexus durante o processo de build/deploy, interrompendo o fluxo de release da aplicação.

✅ O que você deve fazer:

  1. Validar se os arquivos transpilados estão sendo gerados na pasta dist.
  2. Ajustar o tsconfig.json garantindo "outDir": "dist".
  3. Verificar e remover/ajustar o script prepublish no package.json.
  4. Garantir que dependências e o TypeScript (tsc) estejam disponíveis no build.
  5. Executar build e testes localmente antes do commit.
  6. Reexecutar a pipeline após correções.

🔍 Possíveis causas:

  • Ausência de geração da pasta dist.
  • Execução indevida de build no prepublish.
  • Falta de dependências no ambiente de build.

🛠️ Etapa de falha:
Publish na esteira Bamboo (npm publish dist --registry ), retornando erro (exit code 1).

🎯 Motivo:
Erro Build

👥 Time responsável:
Desenvolvimento
