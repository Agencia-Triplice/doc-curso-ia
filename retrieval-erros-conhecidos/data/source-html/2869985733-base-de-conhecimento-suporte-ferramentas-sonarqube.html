1.1 Está com 0% de coverage mesmo contendo os testes unitários no projeto - ERROR: Quality Gate com erros. Coverage 0%

🧠 

Resposta da BIA TECH – A etapa SonarQube Quality Gate Check falhou devido à configuração incorreta do plug-in JaCoCo

Olá! 👋
Identificamos que a etapa SonarQube Quality Gate Check falhou. Esse problema pode estar relacionado a falta de cobertura suficiente de testes unitários no projeto. Inicialmente deve ser verificado se os testes estão corretamente

na pasta src/java/test. Caso já estejam corretamente configurados, o relatório de testes para Sonar é gerado a partir do plugin do Jacoco. Localmente e dentro da pasta do seu projeto, você pode rodar os comandos abaixo e verificar o relatório dentro da pasta target:

  • mvn clean install jacoco:report - compila, executa, e gera relatório de cobertura
  • mvn jacoco:report - gera relatório de cobertura

Caso o relatório dentro da pasta target foi gerado corretamente, valide a cobertura se atingiu 90% e caso não deverá aumentar a cobertura. Caso atingiu 90%, o problema pode estar relacionado a configuração do plugin do Jacoco e do maven-surefire no pom.xml. Se for o caso esse problema resulta em 0% de coverage de testes unitários pelo quality gate do Sonar. Se você estiver tendo problemas de 0% de coverage mostrado no log da execução do workflow pelo GitHub Actions é muito provável que há alguma incosistência no pom.xml relacionado ao plugin do JaCoCo.  A versão recomendada deste plugin deve ser a 0.8.11. Segue um exemplo de configuração do Jacoco e do maven-surefire.

<plugin>
                <groupId>org.jacoco</groupId>
                <artifactId>jacoco-maven-plugin</artifactId>
                <version>0.8.11</version>
                <configuration>
                    <excludes>
                        <exclude>${sonar.coverage.exclusions}</exclude>
                    </excludes>
                </configuration>
                <executions>
                    <execution>
                        <goals>
                            <goal>prepare-agent</goal>
                        </goals>
                    </execution>
                    <execution>
                        <id>report</id>
                        <phase>test</phase>
                        <goals>
                            <goal>report</goal>
                        </goals>
                    </execution>
                </executions>
</plugin>

<plugin>
                <groupId>org.apache.maven.plugins</groupId>
                <artifactId>maven-surefire-plugin</artifactId>
                <version>${maven-surefire-plugin.version}</version>
                <configuration>
                    <runOrder>random</runOrder>
                </configuration>
</plugin>

🛠️ Etapa de falha

SonarQube Quality Gate Check

🔍 O que isso significa?

Como consequência, o SonarQube não está interpretando corretamente o arquivo jacoco.xml, comprometendo a análise de cobertura.

✅ O que você deve fazer:

       1. Verificar se os testes estão corretamente configurados dentro da pasta src/java/test.

       2. Utilizar os comandos do maven para executar testes/gerar relatório ou só gerar o relatório localmente. Se a cobertura estiver abaixo, deverá aumentar a cobertura. 

       3. Ajustar a configuração dos plugs-in do Jacoco e maven-surefire conforme a documentação oficial.

1.2  Sua analise esta quebrando na checagem de quality gate - ERROR: Quality Gate com erros.

🧠 

Resposta da BIA TECH – A etapa SonarQube Quality Gate Check falhou devido à apontamentos encontrados no código do projeto

Olá! 👋
Identificamos que a etapa SonarQube Quality Gate Check falhou. Esse problema ocorreu porque as métricas definidas no quality gate do seu projeto não foram atendidas. Inicialmente deve ser verificado o relatorio gerado pelo SonarQube para identificar quais métricas geraram bloqueio.

No log da execução da sua Pipeline, voce deve procurar pelo status "Quality Gate com erros. Visite o relatório clicando no link:". O link subsequente ao status levará você ate a dashboard do seu projeto no SonarQube, onde poderão ser validadas quais métricas geraram bloqueios.


🛠️ Etapa de falha

SonarQube Quality Gate Check

🔍 O que isso significa?

O SonarQube identificou apontamentos no código do projeto e esta bloqueando o avanço da pipeline para que os apontamentos sejam corrigidos.

✅ O que você deve fazer:

       1. Verificar o relatório da análise para identificar os apontamentos.

       2. Providenciar a correção dos apontamentos ou solicitar uma análise de "exclusion temporário" via fluxo Bex. 

       3. Após a correção ou aplicação do "exclusion temporário", reexecutar o workflow da sua pipeline para avançar o step anteriormente bloqueado.

1.3  Falha ao executar login na plataforma SonarQube.

🧠 

Resposta da BIA TECH – A tentativa de login na plataforma SonarQube foi falha

Olá! 👋
Identificamos falha na tantativa de login no SonarQube. Esse problema pode ocorrer por alguns motivos:

  • Case sensitive na chave de login.
  • Chave de login "duplicada".
  • Falta de grupos de acesso a projetos.

🛠️ Etapa de falha

Login na plataforma

🔍 O que isso significa?

O SonarQube não foi capaz de validar o seu login devido aos possíveis erros supracitados.

✅ O que você deve fazer:

       1. Case sensitive na chave de login:

    • Abrir uma aba anonima do seu navegador.
    • acessar a url: https://sonarqube.bradesco.com.br:8443/sonarqubeenterprise
    • Testar o login da sua chave com letra maiuscula e minuscula: M000000 ou m000000.
    • Em caso de persistencia da falha, abrir um chamado no Bex para a fila: Ferramentas > Suporte Sonarqube e Anexar as evidências das tentativas de login.

       2. Falta de grupos de acesso a projetos.:

    • Validar via Bex se voce possui os grupos de acesso ao projeto, Link consulta de acessos.
    • Caso não possua os grupos de acesso, solicitar via Bex, Link para solicitar grupos de acesso.
    • Em caso de persistencia da falha, abrir um chamado no Bex para a fila: Ferramentas > Suporte Sonarqube e Anexar as evidências das tentativas de login.

       3. Chave de login "duplicada". 

    • Para casos em que as supracitadas ações não surtam efeito, o cadastro do seu usuário esta duplicado dentro da plataforma SonarQube.
    • Deverá ser aberto um chamado no Bex para a fila: Ferramentas > Suporte Sonarqube e anexar as evidências das tentativas de login.

🎯 Motivo:

Falha Login

👥 Time responsável:

1.4  Falha para visualizar projetos dentro da plataforma SonarQube.

🧠 

Resposta da BIA TECH – Falha para visualizar projetos dentro da plataforma SonarQube

Olá! 👋
Identificamos falha na visualização de projetos dentro do SonarQube. Esse problema pode ocorrer por alguns motivos:

  • Falta de grupos de acesso ao projeto.
  • Projeto com falha de "permission template".

🎯 Motivo:

Falha visualização de projetos

🛠️ Etapa de falha

Acesso dashboard

🔍 O que isso significa?

Não foi capaz de visuzalizar a dashboard do seu projeto devido aos erros supracitados.

✅ O que você deve fazer:

       1. Falta de grupos de acesso ao projeto:

    • Validar via Bex se voce possui os grupos de acesso ao projeto, Link consulta de acessos.
    • Caso não possua os grupos de acesso, solicitar via Bex, Link para solicitar grupos de acesso.
    • Em caso de persistencia da falha, abrir um chamado no Bex para a fila: Ferramentas > Suporte Sonarqube e anexar as evidências do login e falha na visualização do projeto.

       3. Projeto com falha de "permission template". 

    • Para casos em que as supracitadas ações não surtam efeito, o referido projeto esta com falha de configuração dentro da plataforma SonarQube.
    • Deverá ser aberto um chamado no Bex para a fila: Ferramentas > Suporte Sonarqube e anexar as evidências do login e falha na visualização do projeto.

🎯 Motivo:

Apoio pontual


👥 Time responsável:
